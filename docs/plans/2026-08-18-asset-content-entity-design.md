# AssetContent Entity Design

**Date:** 2026-08-18  
**Task:** 2.1 — Add JPA module and AssetContent entity

## Goal

Add a reusable persistence module that owns physical blob metadata without coupling the core module to JPA or coupling persistence to Spring.

## Architecture

Create `dedup4j-jpa` as a Maven child module. The module uses Jakarta Persistence for its public mapping contract, Hibernate ORM as the persistence implementation, and H2 only for tests. It does not depend on Spring or storage-provider SDKs.

`AssetContent` maps to `blob_asset_content` and owns the physical content identity, object location, optional content metadata, reference count, timestamps, and optimistic-lock version. The database identity invariant is enforced by a unique constraint over `hash_algorithm`, `content_hash`, and `size_bytes`.

## Entity Mapping

The entity contains:

- UUID primary key generated by the persistence provider.
- Required `hashAlgorithm`, `contentHash`, and `sizeBytes` content identity fields.
- Required `objectKey`, `storageProvider`, and `bucketOrContainer` object location fields.
- Optional `contentType` and `originalExtension` metadata fields.
- Required `refCount`, initialized to one for newly stored content.
- Required `createdAt` and `updatedAt` timestamps maintained through portable JPA lifecycle callbacks.
- A required optimistic-lock `version` field.

Named indexes cover content hash, object key, and reference count. Repository operations, row locks, and reference-count mutations remain outside Task 2.1.

## Testing

`AssetContentMappingTest` boots a real Hibernate persistence unit backed by an in-memory H2 database. It verifies that a valid entity can be persisted and read with generated identity, timestamps, initial reference count, and version state. Focused mapping assertions verify the required table name, unique content-identity constraint, and named indexes.

This test boundary proves both the declared mapping contract and Hibernate's ability to generate and use the schema without introducing Spring.

## Error Handling and Scope

Constructor arguments that represent required metadata reject null, blank, or invalid values before persistence. Optional metadata remains nullable. No entity callback performs storage I/O, and no logical application asset schema is introduced.
